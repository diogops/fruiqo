# Relatório de Compliance de ToS/APIs — Fase 0 — Fruiqo

Auditor: tos-compliance-auditor. Data de acesso a todas as fontes: **2026-09-27**.

Aviso de método: este relatório mapeia cláusulas de documentos oficiais (Termos de Serviço, Developer Policy, API Terms, Guidelines de review de loja e legislação) para as capacidades pretendidas do Fruiqo, nos dois cenários definidos em `docs/phase0/platforms.md`. Regra fail-closed aplicada: toda afirmação sem URL oficial + trecho parafraseado é `NÃO VERIFICADO` e tratada como proibida até prova em contrário. Nenhuma decisão de arquitetura é tomada aqui — isso é papel do `phase0-arbiter`.

Nota sobre esta revisão (2026-09-27, rodada complementar): as 21 plataformas originais (seções abaixo) não foram reabertas. Foram acrescentadas somente as 5 plataformas de stack mobile registradas em `docs/phase0/platforms.md` e sinalizadas como lacuna (contradição C-09) em `docs/phase0/decision-matrix.md`: P-EXPO, P-SHARE-PLUGIN, P-APPLE-DEV, P-WEBSHARE e P-IOS-SHORTCUTS.

A leitura mais permissiva (uso pessoal, sem redistribuição, sem dano ao serviço) é plausível mas não confirmada por nenhuma exceção documentada.

## 4. LGPD

| Dado | Titular | Finalidade | Base legal sugerida | Retenção sugerida | Transferência internacional | Risco |
|---|---|---|---|---|---|---|
| Texto/caption do post compartilhado (Instagram/TikTok/YouTube) | Usuário do Fruiqo (titular direto) e, potencialmente, terceiros mencionados/marcados no post | Extração de recomendações de música/filmes/séries via LLM | Execução de contrato (Art. 7º, V) para a finalidade principal do app; a confirmar com parecer jurídico se exige também consentimento específico dado o conteúdo poder incluir dados de terceiros | Mínimo necessário para o processamento; alinhar ao TTL de retenção da Anthropic (30 dias, salvo sinalização) e purgar cópia local após conclusão do fluxo | Sim — se o processamento LLM ocorrer via API Anthropic hospedada fora do Brasil | Médio-alto: dado de terceiro incidental (pessoa citada/marcada no post) sem relação contratual direta com o Fruiqo; exige minimização e possivelmente anonimização antes do envio ao LLM |
| Imagens do post (capas, fotos) | Usuário do Fruiqo / titular do conteúdo original (pode ser terceiro, ex.: criador do post) | OCR/extração visual de recomendações | Execução de contrato / legítimo interesse (a confirmar) | Curto prazo, apenas durante o processamento; preferir OCR on-device (ML Kit/Vision) para minimizar transferência | Não, se OCR for on-device (P-MLKIT/Apple Vision); Sim, se a imagem for enviada ao LLM multimodal da Anthropic | Médio: imagem pode conter rostos/dados sensíveis incidentais; preferir pipeline on-device quando possível para reduzir superfície de transferência internacional |
| Tokens OAuth de streaming (Spotify, Apple Music, etc.) | Usuário do Fruiqo | Autenticação e ações no serviço de streaming (busca, playlist, playback) em nome do usuário | Execução de contrato (Art. 7º, V) | Enquanto a conta estiver ativa; revogável a pedido do titular; nunca armazenar client secret no app (premissa já fixada no CLAUDE.md) | Depende de onde o backend do Fruiqo está hospedado; se backend fora do Brasil, é transferência internacional | Alto se mal protegido: token de acesso a conta de streaming é dado sensível operacionalmente (acesso a conta de terceiro), exige criptografia em repouso e escopo mínimo de permissões OAuth |
| Histórico de consumo/recomendações geradas (o que foi extraído, resolvido e/ou adicionado ao streaming) | Usuário do Fruiqo | Personalização, histórico de uso, eventual melhoria de produto | Execução de contrato para o histórico funcional; legítimo interesse (a confirmar) se usado para métricas/produto | Definir prazo máximo (ex.: enquanto a conta existir + período de graça pós-exclusão); direito de exclusão do titular deve ser operacionalizável | Depende da hospedagem do backend | Médio: histórico de consumo cultural pode revelar preferências pessoais (não necessariamente dado sensível no sentido do Art. 5º, II, mas relevante para perfilamento) |
| Metadado de identificação do usuário (e-mail, nome, ID de conta) | Usuário do Fruiqo | Conta de acesso ao app, comunicação | Execução de contrato / consentimento no cadastro | Enquanto a conta existir | Depende da hospedagem | Baixo-médio: dado cadastral padrão, risco usual de qualquer app com conta de usuário |
| Código-fonte, ativos de build e credenciais de assinatura (certificado Apple, keystore Android, API keys de submissão) processados pelo EAS Build | Fruiqo (pessoa jurídica/física responsável pelo projeto) — não é dado pessoal de usuário final do app, mas é segredo/ativo sensível da operação | Compilação e assinatura de código para distribuição do app | Não aplicável no sentido de dado pessoal de titular externo; é tratamento de segredo próprio via subprocessador (Expo/Google Cloud) | Conforme política da Expo: logs/artefatos 90 dias; app-specific passwords Apple, período da submissão + 24h; credenciais cifradas em KMS enquanto ativas | Sim, se os servidores de build/armazenamento da Expo estiverem fora do Brasil (não confirmado nesta pesquisa) | Baixo-médio do ponto de vista de dado pessoal (não é dado do titular final), mas relevante para gestão de segredos/fornecedores (SEC-REQ-10); não gera obrigação de titular sob a LGPD, mas é boa prática documentar o subprocessador |

Observações LGPD adicionais:
- Direitos do titular (Art. 18 LGPD) — confirmação de tratamento, acesso, correção, anonimização/eliminação, portabilidade, revogação de consentimento — precisam de mecanismo operacional no app/backend, independentemente do cenário (SC-PERSONAL com 1 usuário ainda é "tratamento de dados pessoais" sob a LGPD, que não distingue por escala de uso).
- Transferência internacional: a Resolução CD/ANPD nº 19/2024 permite cláusulas contratuais padrão publicadas pela ANPD como mecanismo formal; verificar se a Anthropic (fornecedor da API LLM) oferece Data Processing Addendum compatível com LGPD/cláusulas padrão brasileiras, ou se será necessário usar cláusulas contratuais específicas.
- Dado de terceiro incidental (pessoa citada/mencionada em um post compartilhado, mas que não é usuária do Fruiqo) é o ponto mais delicado: o Fruiqo não tem relação direta com esse titular e não pode obter consentimento dele; a base legal mais defensável é legítimo interesse com teste de proporcionalidade e minimização — mas isso exige parecer jurídico específico (ver pendências).
- EAS Build (Expo) não é, por si, um tratamento de dado pessoal de usuário final relevante para a LGPD (a própria Expo declara não ter acesso a PII dos usuários finais do app cliente), mas é um subprocessador que manuseia segredos da operação (código-fonte, credenciais de assinatura) — vale documentá-lo no inventário de fornecedores por boa prática de governança, mesmo sem gerar uma obrigação direta de titular.
